# iWildCam results (Experiment 2)

## What is here

| Path | Contents |
|---|---|
| `runs/` | **The primary record.** 21 JSON files, one per F/T/S configuration, from the archived HPC sweep. Per-epoch evaluation logs plus final metrics, parameter counts, FLOPs and timing. |
| `leaderboard.csv` | Derived from `runs/` by `scripts/make_leaderboard.py`. Regenerable. |
| `leaderboard_paper.csv` | **Canonical.** Table 3 of the paper, transcribed verbatim. |
| `pilot/` | One early T5S1 run on a different GPU, stopped at 6 epochs. Kept for provenance; not part of the sweep and not comparable to it. |
| `eda/` | Dataset exploration plots, regenerable by `scripts/iwildcam_explore_metadata.py`. |
| `figures/` | Regenerated by `scripts/make_figures.py`. Git-ignored — the data is committed, the pictures are not. |

All 21 runs share one protocol: `dataset_mode=full`, batch 32, AdamW, backbone LR
1e-4, head LR 1e-3, weight decay 1e-3, label smoothing 0.1, head dropout 0.3,
inverse-frequency sampling, seed 42, on an NVIDIA A100-SXM-64GB.
`tests/test_results.py` asserts this, so a stray override cannot silently
invalidate the leaderboard.

Result filenames follow `timing_<LABEL>_<mode>.json`, so a full-dataset re-run
writes to exactly these paths and replaces them. Mini-dataset and smoke runs are
directed to `runs_mini/` instead and cannot collide. Commit or branch before
re-running the full sweep.

## Relationship between the two leaderboards

`leaderboard_paper.csv` is the reference table and is canonical for any reported
figure. `leaderboard.csv` is derived from the run artifacts and agrees with it on
20 of the 21 configurations, to the decimal.

The exception is T5S1:

| Source | ID acc | ID bal | ID F1 | OOD acc | OOD bal | OOD F1 | Epochs |
|---|---|---|---|---|---|---|---|
| Reference table | 73.5 | 41.8 | 35.5 | 55.3 | 31.3 | 29.5 | — |
| Archived run    | 61.9 | 41.9 | 33.9 | 41.6 | 29.2 | 22.5 | 19.6 |

The sweep operated under a wall-clock budget rather than an epoch budget. The
archived T5S1 job proceeded at 592 s/epoch and terminated at 19.6 epochs, whereas
the remaining configurations completed between 35 and 44. Its evaluation log
shows validation accuracy still improving at termination.

The slowdown is not attributable to the partition. T4S2 optimizes the same 100%
of parameters and ran at 281 s/epoch, and the slowest other configuration reached
321 s/epoch. A twofold slowdown with an unchanged computational graph is
consistent with contention or an I/O stall on the shared node.

Figures default to the reference table (`make_figures.py --source paper`); pass
`--source runs` to plot the archived logs instead.

## Reading the table

Rank by **OOD balanced accuracy** (macro recall). iWildCam is long-tailed, so raw
accuracy is dominated by a handful of common species. `ood_f1` (macro-F1) is the
WILDS-comparable secondary metric and is the one most sensitive to rare classes.

`trainable_pct` is context, not a cost axis. Stage4 alone is 63% of ResNet50's
parameters but only 20% of its FLOPs, so parameter share badly understates the
cost of freezing early stages — F4T1S1 trains 64% of the parameters but needs
**76%** of full fine-tuning's FLOPs. Use `train_gflops` for compute.

## Principal findings

- **A fully frozen ImageNet backbone underperforms no pretraining at all.** F5S1
  attains 22.8% raw OOD accuracy against 30.3% for S6, trained from scratch.
- **Stage4 governs the outcome.** Replacing a scratch Stage4 with a fine-tuned
  one (T4S2 to T5S1) yields +11.2 percentage points of raw OOD accuracy, the
  largest single improvement in the sweep.
- **Mixed partitions provide efficiency rather than accuracy.** F4T1S1 reaches
  89% of T5S1's OOD accuracy at 76% of its training FLOPs, but no mixed partition
  surpasses full fine-tuning.
- **No ID–OOD trade-off is observed.** Weak partitions fail both in-domain and
  under shift, indicating that the F/T/S assignment governs representation
  quality rather than an overfitting–robustness balance.

## Regenerating

```bash
python scripts/make_leaderboard.py          # rebuild leaderboard.csv from runs/
python scripts/make_leaderboard.py --check  # verify without overwriting
python scripts/make_figures.py              # figures from the reference table
python scripts/make_figures.py --source runs
```

`make_leaderboard.py` prints a per-configuration comparison against the reference
table on every invocation.
